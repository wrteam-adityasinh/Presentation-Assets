# Key features slide (03-features)

The marketplace buyer is building an app for *their* customers. This slide shows what the finished app lets those customers do.

## How to find features

1. Read the visible text on every main screen (`analyse-page.js` with `WITH_TEXT = true`).
2. List what the screens let a user *do*: book, pay, chat, plan, filter, track, upload, verify, generate, listen offline…
3. Merge duplicates. Keep the 6–8 strongest, ordered by how central they are to the product.
4. For each feature, note the screen id that proves it. **No screen, no feature.**

## How to write each feature

- **Name**: 2–4 words, a capability, not a screen. "Plan dates in chat", not "Chat screen".
- **Benefit line**: one sentence, max ~60 characters, from the customer's side: what they get or save.
- **Icon**: an instance of one of the kit's own icons, or the emoji/mood icon set if the kit has one.
- **Proof**: a small crop (about 280×220) of the screen area that shows the feature.

## Examples from shipped decks

| Product | Feature | Benefit line |
|---|---|---|
| Bondly | Match of the Day | One hand-picked profile every day, worth saying hi to |
| Bondly | Plan dates in chat | Propose a place and time without leaving the conversation |
| Musinto | AI Mix | Describe your mood and get a fresh mix in seconds |
| Musinto | Search by vibe | Find songs by describing them, not only by name |
| PlugNPark | Live charging | Watch charge level, energy and cost in real time |
| Aurenix | Voice mode | Talk, show the camera and listen, hands-free |

## Bad examples

- "Beautiful UI" (about the kit, not the customer)
- "Settings screen" (a screen, not a capability)
- "Fast and secure" (no screen proves it)
- "4.9 rating from 2,000 users" (invented number)

## Layout

Follow the deck's style recipe: tracklist rows (liner notes), polaroid cards (scrapbook), chat answers (prompt → response), bento cards (bento house), receipt lines (neo-brutal)… Keep all cards the same size and alignment.
